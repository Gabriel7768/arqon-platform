# ARQON Architecture Refactoring — Build a Reusable Column Detection Engine

Before implementing P1-3, stop and refactor the architecture.

Do **not** improve the existing regex-based column detection inside the Revenue Engine.

Instead, extract it into a standalone reusable package.

## Goal

Create a production-grade **Column Detection Engine** that becomes the single source of truth for every data import in ARQON.

This engine must be completely independent from the Revenue Engine and reusable by every future connector.

Expected package:

packages/
column-detection-engine/

The Revenue Engine must consume this package instead of containing its own detection logic.

Future integrations (HubSpot, Stripe, Pipedrive, Google Sheets, QuickBooks, ERP connectors, CSV imports, APIs) must also consume this exact package without duplicating logic.

---

# Responsibilities

The Column Detection Engine must be responsible for:

• automatic column detection

• confidence scoring

• conflict detection

• ambiguity resolution

• synonym matching

• normalization

• manual override support

• validation

• mapping explanation

• mapping diagnostics

It must not contain any business logic related to revenue, findings, invoices, opportunities, recommendations, or financial calculations.

Its only responsibility is semantic schema detection.

# Manual Overrides

The engine must support user-defined mappings.

User mappings must always override automatic detection.

Automatic detection must never overwrite manual mappings.

---

# Extensibility

The engine must be fully data-driven.

Adding support for a new ERP, CRM or Accounting platform should require only extending dictionaries and concept definitions.

No engine code should need modification.
