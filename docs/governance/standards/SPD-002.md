## 1. Package Overview

| Aspect | Value |
|---|---|
| Package | `@workspace/billing` (to live in `packages/billing`) |
| Purpose | Reusable payment/billing platform package; creates PIX charges, receives webhook updates, tracks charge status |
| Provider | Abacatepay (`https://api.abacatepay.com/v1`) |
| Responsibilities | Charge creation, charge listing, webhook ingestion, status reconciliation, secrets management, idempotency |
| Architectural boundaries | Independent of Revenue Engine, Auth, DB schema, UI. Talks only to Abacatepay API + exposes a typed interface to the platform |
| Dependencies (upstream) | None platform-internal; outbound HTTPS to Abacatepay |
| Dependents (downstream) | `@workspace/api-server` (creates charges, handles webhook), future subscription/billing flows |

### 1.1 Strategic note (CTO)

Per D-004 (value × simplicity), `packages/billing` is the **first package to
reach implementation**. Without billing the SaaS cannot collect revenue. The
provider (Abacatepay) was verified against its live API documentation (facts
recorded in AGENTS.md). This SPD scopes a **thin first slice**: PIX one-time
charges + webhook status updates. Credit card, subscriptions, coupons, and
withdrawals are explicitly out of the first slice.

### 6.1 First executable slice scope

To reach value fastest, the first slice implements:
- **createCharge** (PIX, ONE_TIME) → returns Abacatepay billing `url` + `id`.
- **handleWebhook** (verify secret/signature, idempotent, update status).
- **getCharge / listCharges** (read-through).
- Charge status reconciliation via BILL-SM states.

Explicitly out of first slice: credit card, subscriptions, coupons, withdraws,
customers CRUD (only inline `customer` on charge creation), refunds (status
reflected, not initiated).

## 7. Risk Analysis

| Risk | Mitigation |
|---|---|
| Abacatepay dev-mode vs prod key confusion | BILL-SEC mandates key is env-only; `devMode` flag surfaced from response |
| Webhook secret in query string (lower security than HMAC header) | BILL-SEC requires BOTH: accept query secret per docs AND verify `X-Webhook-Signature` if present; fail closed |
| Duplicate webhook processing | BILL-RT mandates idempotency by event id (SEC-R8) |
| Abacatepay API change (e.g., new methods beyond PIX) | BILL-ADAPT isolates provider surface; adapter major bump absorbs change |
| Money/cents representation errors | Price is integer centavos BRL, min 100; BILL-API enforces type |
| No TEST-001 standard yet | BILL-TEST authored against RT-001 postconditions; TEST-001 gap tracked |
