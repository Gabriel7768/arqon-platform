## 1. Package Overview

| Aspect | Value |
|---|---|
| Package | `@workspace/i18n` (to live in `packages/i18n`) |
| Purpose | Reusable, white-label, multi-tenant internationalization platform |
| Responsibilities | Locale loading, formatting, fallback, caching, runtime language switching, tenant dictionaries, adapter surfaces (React, Email, PDF, Notification) |
| Architectural boundaries | Independent of Revenue Engine, API, Auth, DB, business rules, UI components |
| Dependencies (upstream) | None platform-internal; only language data + formatter libs |
| Dependents (downstream) | Every ARQON module that renders user-facing text |

### 1.1 Strategic note (CTO)

`packages/i18n` is the package that originally drove the governance corpus
(ADR-001 through ADR-008). It remains a valid and eventually-necessary package.
Per the founder-confirmed priority (value × simplicity), **implementation of
i18n is sequenced AFTER billing and auth**. SPD-001 plans the package fully so
it is ready when its turn comes; it does not advance i18n ahead of billing.

## 4. Writing Order

| Step | Document | Why it depends on prior |
|---|---|---|
| 1 | I18N-ARCH-1.0.0 | Foundational; defines boundaries every other spec lives within |
| 2 | I18N-API-1.0.0 | Defines symbols that RT/SM/adapters reference |
| 3a | I18N-RT-1.0.0 | Defines runtime flows cited by API and adapters |
| 3b | I18N-SM-1.0.0 | Defines states cited by RT and API (parallel to 3a after ARCH+API) |
| 3c | I18N-SEC-1.0.0 | Independent of RT/SM; needs only ARCH |
| 4 | I18N-ADAPT-* (4 adapters) | Need API + RT to map against |
| 5 | I18N-TEST-1.0.0 | Needs RT postconditions and error paths |
| 6 | I18N-OBS / I18N-DEPLOY | Non-blocking; may follow implementation |

## 7. Risk Analysis

| Risk | Mitigation |
|---|---|
| Missing SEC-001 standard | SEC-001 must be authored before I18N-SEC can be frozen; tracked as a gap |
| Circular dependency between RT and SM | Graph is acyclic; SM and RT are parallel after ARCH+API, citing each other by ID only |
| Adapter scope creep | First slice = React only; Email/PDF/Notification deferred |
| Governance-to-delivery ratio | i18n implementation sequenced after billing + auth per D-004 |
| Locale data bundling for multi-host | I18N-DEPLOY addresses Vercel/Render bundling; non-blocking for first slice |

5. Author I18N-SEC-1.0.0 → freeze.

7. Author I18N-TEST-1.0.0 → freeze.
8. **Implementation readiness reached** for first slice (en-US + pt-BR, React).
9. Email/PDF/Notification adapters + OBS/DEPLOY follow incrementally.

> Note: per priority D-004, billing (SPD-002) and auth are implemented before
> i18n. This roadmap prepares i18n so it is ready when its turn comes.
