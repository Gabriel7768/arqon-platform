## 1. Package Overview

| Aspect | Value |
|---|---|
| Package | `@workspace/auth` (to live in `packages/auth`) |
| Purpose | Reusable authentication logic: password hashing, JWT sign/verify, session types, token validation |
| Provider | None external — uses `bcryptjs` (hashing) + `jsonwebtoken` (JWT) |
| Responsibilities | Password hash/compare, token sign/verify, payload typing, secret loading, fail-closed on missing secret |
| Non-responsibilities | HTTP routes (stay in api-server), DB persistence (caller owns), session storage, OAuth |
| Architectural boundaries | Independent of Express, DB, api-server. Pure logic library consumed via `@workspace/auth` |
| Dependencies (upstream) | `bcryptjs`, `jsonwebtoken` |
| Dependents (downstream) | `@workspace/api-server` (will eventually replace `lib/auth.ts`; connection is a future task) |

### 1.1 Strategic note (CTO)

Auth already exists and works in `artifacts/api-server/src/lib/auth.ts`. This
package extracts the **pure auth logic** into a governed, tested, spec-driven
library — without touching the working api-server routes (per "sequência
pura, pacotes isolados"). The api-server will migrate to `@workspace/auth` in
a future task. This closes three gaps: (1) no specs, (2) no isolated tests,
(3) insecure secret fallback (`?? "arqon-dev-secret"`).

### 1.2 First slice scope

- `hashPassword` / `comparePassword` (bcrypt, 10 rounds)
- `signToken` / `verifyToken` (JWT, configurable expiry)
- `AuthPayload` type (`{ userId, email }`)
- `loadSecret` — reads `SESSION_SECRET`, **fails closed** if missing (no insecure fallback)
- `AuthClient` — configurable secret + expiry

Out of first slice: OAuth, refresh tokens, session store, rate limiting,
password reset, MFA, role-based helpers (role is in payload but no RBAC logic
in first slice).

## 7. Risk Analysis

| Risk | Mitigation |
|---|---|
| Secret fallback ("arqon-dev-secret") leaks in prod | AUTH-SEC mandates fail-closed: throw if `SESSION_SECRET` missing |
| Duplicated auth (api-server + package) during migration | Documented as expected; migration is a future task; package is additive |
| bcrypt/jwt version drift vs api-server | Package pins same versions as api-server (`bcryptjs@3`, `jsonwebtoken@9`) |
| Token payload shape change breaks api-server | AUTH-API marks payload Stable; breaking change = major bump + ADR |
| Password hashing cost (10 rounds) too low/high | AUTH-SEC states the policy; configurable via AuthClient but default 10 |
